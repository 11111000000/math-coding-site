Proposition

The v1.0 documentation site is plain HTML + CSS rendered from math/<name>/packet.md at build time, with no JavaScript framework and no client-side dependencies.

Antithesis

v0.993 had a Pandoc-based site build that required pandoc installed on the host. Pandoc is heavyweight and added a third-party dependency to the convention's A3 (Material Basis) property.

Synthesis

Each packet's packet.md is read by an OCaml script that produces a static HTML page. CSS lives in site/assets/tokens.css (no CDN, no JS). Build is one `dune build` invocation. A single HTML index.html lists all packets with axiom + proposition + status.

Body

Intent

git history, one binary. No third-party templating, no JS framework. Documentation follows the same discipline as code: plain text,

What this is NOT

- Not a single-page app. Every page is a real HTML file with real content. - Not a CMS. The site IS the math/ directory. - Not a static site generator (Jekyll, Hugo). Just a 200-line OCaml script.

./math-coding site # regenerates dist/ dune build ```sh 


## Notes

Total build artifact: ~150 KiB HTML+CSS. CSS variables for paper+ink
palette. One accent per epistemic/lifecycle instrument: axiom (blue),
antithesis (crimson), synthesis (green), proof (sepia).

Pages emitted per packet:
- index.html — axiom index with status
- math/<name>.html — full packet page with proposition/notes
- axioms.html — seven axioms overview
- installing.html — how to install math-coding v1.0
